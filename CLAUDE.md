# cc-mod-ferro

A Claude Code mod for fun: Ferro (Vatra's dog, a female Norwich Terrier) runs across a pixel-art meadow in a band above the prompt while Claude works on a long turn. Built 3-4.10.2026. Vatra wants nothing interactive ("so I don't miss anything when I'm not looking"), so the mod only displays. The leverage check from `personal-os/tasks/someday/claude-code-mods.md` was skipped on purpose, because fun is the only goal.

Code, comments, docstrings, script output, test names, UI text (alt), CLAUDE.md, notes in `assets/ref/` and commit messages. ## How it works
- `turn.start` starts three timers: after 20 s the phase is `run`, after 3 min `sleep` (she lies down), and 4.8 s later (`SLEEP_INTRO_MS`) `asleep`. `turn.complete` of the main turn (no `agentId`) cancels them and resets the phase to `null`. The phase lives in `$.state` (`cc-mod-ferro.phase`).
- **The background is random per turn** (Vatra, 4.10.2026: "Random"). `turn.start` draws an index into `SCENES` (`cc-mod-ferro.scene`), so running and sleeping in the same turn share a background. The list of backgrounds is `BACKGROUNDS` in `build.py` and in `scene.py` (there with the place for the alt text, e.g. "the autumn meadow"). Built: `meadow` (summer), `autumn` and `winter`. The mod picks only from `IN_MOD` in `scene.py`: summer and autumn. Winter is switched off for now (Vatra, 4.10.2026); it is still built and previewed, so turning it on is one word in `IN_MOD`.
- **Each turn plays a program** (0.9.0, 6.10.2026; Vatra: not every activity every time, and more activities are coming). A program is one run with a stop every 6-12 s (`GAP_S`), the first one too (12-22 s and the first at 16 s until 7.10.2026, when Vatra wanted less waiting; the first at 5 s was too soon, he wanted it like the later gaps): a turn that ends at 79 s now sees 3.4 stops on average instead of 2.0, and the first stop starts 26-32 s into the turn instead of 36 s. `RUN_BEFORE` (9 s, the middle of `GAP_S`) is only for the scenes with one stop. Stops start until 160 s of the run (`PROGRAM_S`: the run phase lasts from 20 s to 3 min). SMIL has no randomness, so `scene.py` draws `PROGRAMS` (10) per background with a fixed `SEED`, and `turn.start` picks one (`cc-mod-ferro.program`). The first stops of a background's programs come in exactly the `WEIGHTS` shares (sit 4, sniff 2, drink 1, poop while walking 2, poop in one spot 1; until 0.10.0 sit was 5, as the old 50-20-20-10 per turn, and drinking took its tenth from sitting), because most turns see only the first one or two: measured 6.10.2026 on 30 days of transcripts, half of the turns in which Ferro shows end before 79 s (63% of all turns last over 36 s, 48% over 60 s, 36% over 90 s, 18% reach sleep). Later stops are drawn with the same weights, never the same kind twice in a row, at most one poop per run. With four kinds sitting and sniffing alternated after the poop; drinking (0.10.0) breaks that up. A new kind of stop is one function returning a `Stop` in `scene.py` plus an entry in `STOPS`, `WEIGHTS` and `SAYS` (keep the `WEIGHTS` shares whole in `PROGRAMS`).
- `ui.render` on `AbovePrompt` draws an `Svg` only on Desktop, while `isWorking` is true and the phase is not `null`. All animation is SMIL inside the SVG, and the mod draws it once. **It draws the `Svg` as an image, without `isInteractive`** (since 0.7.3, 6.10.2026), because only then does the band render the PNG frames. Scrolling the band restarts the animation, the same as in the sandboxed frame before (seen in the probe), and so does reopening the conversation. That is why sleeping has two scenes (0.10.1, 7.10.2026): `sleep` lies down first, `asleep` (`sleep_scene(lie_down=False)`) starts breathing straight away, with the clouds started 4.8 s in (`begin="-4.8s"`), so the swap when she has lain down does not show (checked in the preview frame by frame: clouds, breathing and z's match). Before, she lay down again every time Vatra opened a conversation in which she was asleep.
- **Another mod's band goes first** (6.10.2026). Before drawing, the hook calls `await next(e)`; if a plugin beneath drew anything (cc-mod-rm-list with the files of a delete prompt, cc-mod-running-task, cc-mod-routines), Ferro returns that tree unchanged and waits. She draws only when `next(e)` answers `{ type: 'engine', ref }`: the engine's own band, which is empty. Before, she returned her tree without `next(e)`, and in Desktop 2.1.286 she sits above those mods in the chain, so the rm-list band did not show during a long turn. `claude plugin test` has no engine beneath `ui.render` (it refuses to mount until the test answers it), so the tests answer `{ type: 'engine', ref: 0 }`, as the engine's core does (declared in `RenderElement` in the plugin-authoring types). Checked live 6.10.2026 in a new session: during a delete prompt Vatra waited past the 20 s, and the rm-list band stayed the whole time.
- Width: `bodyColumns * 8` CSS px, at most 1280. Without an explicit `width` the frame stays at 300 px. The 8 px per column ratio was measured on 4.10.2026 on the TV (94 columns, ~753 px), not yet on the monitor. The scene has `preserveAspectRatio="xMidYMid slice"`, so a narrower band crops the edges of the scene and the pixels stay 2 CSS px.

## What the Desktop band lets through (test 4.10.2026)
- The Claude Code and Desktop facts the README relies on, with when they were last checked live, are in `docs/desktop-band.md`. Update its `verified` when you check them again.
- Allowed: `<path>`, `<rect>`, `<use href>` and `<use xlink:href>`, `<pattern>`, nested `<svg>`, `<text>`, SMIL (`animate`, `animateTransform`, `set`).
- **Every drawing is a PNG** (since 0.7.3, 6.10.2026): each layer and frame an `<image>` with an indexed-colour PNG in a data URI, in `<defs>`, placed with `<use>`, and `image-rendering="pixelated"` on the root `<svg>` so the 2x pixels stay sharp. **`<image>` does NOT render in the sandboxed frame** (`isInteractive`), only when the `Svg` is drawn as an image, where SMIL animates too (probe 6.10.2026, 2.1.288). A second probe the same evening drew the summer sitting scene from PNG frames above the vector one, and to Vatra they looked the same, as sharp and as wide (details in `docs/desktop-band.md`). Until 0.7.2 every drawing was vector strokes (one `<path>` per colour, a stroke of width 1 per horizontal run of pixels), about six times the size of the PNG.
- The `Svg` element limit is 131,072 characters. A run is `head` + a program's `body` (+ the ball piece). The head is shared by every program of a background: the meadow layers (~5.8k) and every frame of every stop (38 frames), 42,808 in all (summer). With the ball the largest program is 86,669 (summer), 85,803 (autumn) and 87,145 (winter) characters (measured 7.10.2026, with the 6-12 s gaps; with 12-22 s it was 81,980, 81,573 and 83,262); sleeping is ~18k (~11k without lying down). The ball is now the biggest part of a program (it is keyframed over the whole ~3-minute loop), so a longer program or a much shorter `GAP_S` grows it first. A dog frame is ~1,100 (it was ~6,500 as vector strokes). `scene.ts` is ~945k characters. Measure every new drawing or stop: `python tools/scene.py` prints the sizes and fails if a program with the ball is over the limit.

## Drawings and tools
- `assets/src/` holds the original ChatGPT drawings: `run.png`, `poop.png` and `sleep.png` (6 frames each on a magenta background), `meadow.png` (summer meadow, 3:2, nearly seamless) `autumn.png` and `winter.png` (same composition, 4.10.2026). The prompts and the template for a new background are in `assets/ref/chatgpt-project.md`. Key parts: "Norwich Terrier", "side view facing right", "same ground baseline", "flat solid pure magenta (#FF00FF) background", and for backgrounds "edges must match seamlessly".
- `tools/build.py` → `assets/px/`: cuts the frames, removes the magenta, downsamples to a true pixel grid (run factor 6, the rest ~5.5 so the dog is the same size), maps to the shared palette, smooths the edge and aligns the frames on the right ear and the ground. Each background is split into three layers. The split expects the meadow composition: the sky is the most common colour of the third row, the hills start 3 rows above the block of rows that are at least a third not sky and run unbroken to the bottom (white counts as not sky, for snowy hills; the clouds sit above a gap of clear sky), and the grass starts at the first row with 60% light green (yellow-green autumn grass passes too). A ground that is not green (snow) starts on the row after the darkest row under the bushes. Check a new background on the real image before using it: `meadow()` prints where the hills and the grass start, and the summer and autumn layers must stay unchanged (`git status assets/px`).
- **Clouds have their own palette** (4.10.2026): the sky colour plus two cloud colours (white and light-blue shading), computed from the cloud pixels above the hills alone. In the shared 48-colour palette the shading merged into the sky or a grey-green, so the summer clouds were flat white blobs and the autumn ones fell apart into fragments. With it, the summer clouds also got their light-blue underside back, as in the source.
- **The dog palette is frozen** in `assets/palette.json` (4.10.2026): 22 fur and outline colours (`fur`), three shades of the tongue (`tongue`, dark to light, since 7.10.2026) and the eye highlight. Median cut + k-means over all images computed it originally; now `build.py` only gives each pixel the nearest colour from the file. Freezing changed no pixel. A new palette from the images is computed only deliberately: `python tools/build.py --new-palette`, which shifts the colours of every animation. A colour added to `fur` does not change existing colours, but it can take over pixels of existing drawings it is closer to, so after a build `git status assets/px` shows which frames changed. Each background has its own palette (48 colours, from its own image only), so a new dog drawing does not touch it.
- **Extra background colours** (`EXTRA_COLORS`, 4.10.2026): median cut gives colours by pixel count, so the brown trunks and twigs of the winter meadow (under 1% of the pixels) turned near black. For a background listed there, pixels the 48 colours miss by more than 60 (sum of channel differences) get 4 colours of their own (median cut + k-means), and every pixel goes to the nearest colour of the larger palette. Only winter uses it, so the approved summer and autumn layers did not change.
- `tools/scene.py` → `plugin/hooks/scene.ts` (generated, do not edit) and `preview/*.svg`: a scene with one stop of each kind (`run.svg` pooping while walking, `run-still.svg`, `sit.svg`, `sniff.svg`, `drink.svg`, each also `ball-...`) and `sleep.svg` for the summer meadow (`asleep.svg`, sleeping without lying down, is only for viewing and not committed), `<name>-...` for the others. `run_body` builds every run from its stops, so a scene with one stop is a program with one stop. `preview/*.svg` is committed (since 4.10.2026), because the README shows them as animation: commit them after every new scene. The programs of the summer meadow (`program-<i>.svg`, every other one `ball-program-<i>.svg`) and `programs.html`, which lists when each stop starts, are only for viewing and are not committed (`.gitignore`).
- **The repo is public (since 4.10.2026, portfolio).** The README must stay accurate when a drawing, a scene or a number (scene sizes, phases) changes.
- **Frames fixed by hand** (7.10.2026): `assets/fix/<name>-<i>.png` replaces the frame `build.py` makes from the source (76x44, same position on the canvas), before the derived frames, so a rebuild keeps the fix. Edit a copy of the built frame there in a pixel editor (Piskel in the browser), not `assets/px`, which the build overwrites. Vatra fixed sleep-1 and sleep-2 there in Piskel (0.9.1, 49 and 70 pixels; ChatGPT drew them wrong in the source too). Take colours with the eyedropper from the same frame, so the frozen palette holds. Before copying an export in, check it is 76x44, has only alpha 0 and 255 and only palette colours (Piskel's import has "Smooth resize" on by default; at the same size it changed nothing).
- `tools/preview.py` → an enlarged PNG of all frames, for checking by eye.
- `tools/sprites.py` → `preview/sprites.html` (committed, 7.10.2026): the shared reference of every drawing in `assets/px`, one section per animation, enlarged on a checkerboard, with its name and size. A drawing whose data URI is not in `scene.ts` is dimmed and marked "not in the mod" (now run-1, sniff-1 to 4 and the winter layers). Run it after `build.py` and `scene.py`, and commit the page with them.
- `tools/ref_sheet.py` → `assets/ref/ferro-ref.png`, the reference sheet for ChatGPT: three enlarged figures (standing, running with the tongue out, sitting and facing the viewer, zoom 6), the frozen palette (6 columns) and every frame ChatGPT drew, one row per animation at zoom 3 (run, sleep, poop, poop-walk with the droppings, sit), on magenta, 1536x1024. The derived breath and blink frames are left out. With five rows it ends at row 1018 of 1024: a sixth animation needs a new layout (smaller zoom or two short animations in one row), so sniff.png is not on it (6.10.2026). It is built from `assets/px`, so regenerate it after reworking a drawing or the palette.
- Preview in a browser: `preview/index.html` shows all scenes of all backgrounds, `preview/programs.html` the programs. Vatra watches them in his Chrome (Personal profile), not in the Browser pane. `preview_start ferro` (`.claude/launch.json`, here and in personal-os) serves `preview/` on port 8767. Screenshots of a paused SVG (`pauseAnimations`, `setCurrentTime`) often time out in the Browser pane (6.10.2026); check a moment by reading which `<use>` elements show and where (`getComputedStyle`, `getBoundingClientRect`) instead.

## Learned
- **An installed mod does not run in a normal session without a flag** (4.10.2026). Mods of installed plugins sit behind Anthropic's rollout switch, which is off for Vatra's account (`"tengu_plugin_hooks_modules": false` in `~/.claude.json`). Desktop 2.1.286 then does not run the hooks of installed plugins. A mod from `~/.claude/dev-mods` with hot reload on bypasses the switch, so the test in the session worked and the installed version did not. With hot reload on in a session, the installed one works too. The permanent fix is `"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"` in the `env` block of `~/.claude/settings.json`. Check the mod in a normal session only in a new session without hot reload. On 6.10.2026 the switch was on (`true` in `~/.claude.json`), and 2.1.288 turns it on by default.
- **Gallop order:** ChatGPT laid the run frames out without the order of the phases and Ferro looked like she was running backwards. The real order is `[4, 3, 2, 5, 0]` (`RUN_ORDER`): stretched, landing on the front legs, hind legs forward, gathered, push-off. Frame 1 is left out.
- **Tempo:** 0.13 s per frame, because at 0.085 s the legs looked like they twitched. The grass moves at 80 px/s, although a paw on the ground moves ~42 px/s. Vatra prefers a faster background to a perfect stride, and grass blades over the paws did not help.
- **The tongue, eyes and edge were broken by `build.py`, not by ChatGPT** (4.10.2026). The source has a pink tongue (~170 pixels per dog) and a white eye highlight (2-8 pixels), but downsampling turned the tongue maroon (too few pixels for a colour of its own in median cut) and lost the highlight (never the most common colour in a 6x6 block). About 6,400 pixels of magenta fringe next to the background entered the palette as maroon, hence maroon dots along the outline and maroon ears. The fix: the magenta fringe goes to the background, the tongue and the highlight have reserved colours, each highlight becomes one white pixel on the dark eye, and the edge is cleaned (stray pixels and side bumps removed, fur next to the background becomes outline). Without the k-means refinement median cut lost the neutral dark grey and the saddle got brown blotches. The ear used for alignment is measured before the edge is cleaned, so the frame positions stayed the same. Do not "fix" in ChatGPT what downsampling eats - check the source first. Vatra saw the fix in the installed 0.2.1 (4.10.2026).
- **Expansion plan** (Vatra, 4.10.2026): more animations and backgrounds in a consistent style. The palette was frozen before Ferro's design is final, because reworking a drawing with a frozen palette still works. The reference sheet is ready (`assets/ref/ferro-ref.png`), and the ChatGPT Project instructions and message templates are in `assets/ref/chatgpt-project.md`. The autumn and winter backgrounds are in. An animation with a prop (ball, bone) needs `build.py` reworked: it treats every figure narrower than 20 pixels as the pile from `poop.png`. In the Project, attach the reference sheet to every message - the OpenAI documentation does not say that the image generator sees images from the project files.
- **Pooping while walking** (Vatra, 4.10.2026): the real Ferro rarely stops to poop in one spot; she poops while walking slowly forward and leaves a row of droppings over a metre or two. `assets/src/poop-walk.png` (ChatGPT) has a 4-frame hunched walk and three droppings in a separate row. `run_walk_scene` in `scene.py`: run, crouch frames 1-2 of `poop.png`, 7 s of hunched walking at 22 px/s with a dropping at 0.8, 2.5, 4.2 and 5.9 s (largest to smallest, about two dog lengths in all), then frame 5 of `poop.png` and running. Vatra approved it in the preview. **The old stationary scene (`run_scene`) stays as a rare variant**: 10% of the turns (see sitting below).
- **Sitting and looking at the viewer** (Vatra, 4.10.2026: the turn to the camera "looks great"; sitting should come more often than pooping). `assets/src/sit.png` (ChatGPT, prompt in `assets/ref/chatgpt-project.md`): brake, sit down, sit in profile, head three-quarters, facing the viewer, head tilt. ChatGPT drew her bigger with a bigger head: factor 9.0 makes the head the size of the other frames. The frames are aligned on the front toes (`TOES_X`), because the ear moves when the head turns. `blink()` derives `sit-blink.png` from sit-4 (eyes filled with the fur around them, bottom row drawn back as a closed-eye line). `sit()` in `scene.py` plays `SIT` (about 8.9 s, with getting up, see below). Until 0.8.0 each turn picked one kind of stop and repeated it every loop: 60-30-10 (Vatra, 4.10.2026), then 50-20-20-10 with sniffing (Vatra, 6.10.2026). Since 0.9.0 those shares are `WEIGHTS` of the programs (see "Each turn plays a program").
- **Getting up from sitting** (0.10.2, 7.10.2026). She went from half sitting (sit-1) straight into a full gallop, and because the sit frames lie 8 px right of the run frames (aligned on the front toes) she slid back 8 px at the same moment. No new ChatGPT drawing was needed: `sit_up()` in `build.py` derives `sit-up.png` from poop-0 (standing on all fours, head up) moved 8 px right (`SIT_UP_DX`), so its head is where sit-1's head was, and `SIT` ends with it for 0.35 s. A `Stop` with `run_from` (sit's is measured from the two PNGs) sets off from a standstill: the run frames start that far right and slide back to their place in 0.5 s while the ground speeds up (`RUN_START`: 6 px after 0.25 s, 20 px after 0.5 s, then 80 px/s), so she never moves backwards against the grass. `ball_layer` adds the slide to her nose. Vatra chose this of four GIF variants: as it was, standing then a full gallop at once, standing then a gallop that speeds up (chosen), and standing plus one walking step (poop-5) before it. The gallop still resumes in whatever phase the run cycle is in, as after every stop.
- **One highlight per eye**: `catchlights` keeps the largest white speck per dark patch that does not touch the background (an eye, not the outline), within the right 65% and top 60% of the figure. The face toward the viewer has two highlights; every other frame stayed as it was.
- **Chasing the orange ball** (Vatra, 4.10.2026: "in about a third" of the turns). `build.py` draws the 9-pixel ball in code (`ball()`, Ferro's outline, three oranges lit from the top left, one highlight); ChatGPT was not needed. `ball_layer` in `scene.py`: while she runs the ball bounces ahead of her (`BALL_BOUNCE_S`, `BALL_BOUNCE_H`), the gap to her nose swinging between 8 and 52 px; at every stop it rolls on and rests on the grass, far enough that she reaches it just as she runs again (or 40 px when she would reach it sooner), and then it pops up again. It asserts that she reaches it before the next stop. Each run window has a whole number of bounces, so the ball is on the grass when it stops and when it starts. Everything is keyframed over the whole loop, because a separate repeating bounce would drift out of step from the second loop on. `turn.start` picks the ball with `BALL_SHARE` = 1/3 (`cc-mod-ferro.ball`). **The ball is not a separate scene**: `scene.ts` has per background one `head` and the `programs`, each with its `body` plus the ball piece and the index in the body where it goes (`ball`, `ballAt`), and the mod inserts it; the piece brings its own `<defs>`. Previews: `ball-run.svg`, `<name>-ball-run.svg`, `...-ball-run-still.svg`, `ball-program-<i>.svg`.
- **ChatGPT drew the walking dog longer and with a bigger head**, and the droppings too big (the largest a third of the dog). `build.py` scales the dog by 6.8 (the same length as the other frames, a little lower, which suits the crouch; 5.9 would match the ear height but looked too big) and the droppings by 10.5 of their own (`DROPPINGS`), so the largest is 9 pixels wide like the old pile. The ground line comes from the dogs, because the droppings row sits lower.
- **A white speck on a hind leg looked like a hole in the outline** (Vatra, 4.10.2026, in run-3). `catchlights` turned every white speck of the source that landed on a dark pixel into the eye highlight, and the outline is dark too. Now only the largest speck on the head (right 40%, top 60% of the figure) counts, and a highlight that won its block in downsampling takes its neighbours' colour, so every frame has exactly one highlight, in the eye. Only run-3, sleep-1, poop-walk-0 and poop-walk-3 changed.
- **Breathing in sleep is done in code, not in ChatGPT** (4.10.2026). Breathing used to alternate between two ChatGPT drawings (sleep-4 and sleep-5), which are two different poses, so the picture jumped. Now `build.py` derives `sleep-breath-1` from sleep-5: the whole back from the loin to the neck (columns 17-35) raised by one pixel, with the head, tail and paws in place. `scene.py` loops it by `BREATH` (still 1.8 s, inhale 1.2 s: 3 s per breath), and sleep-4 stays the last step of the intro. A subtle movement on the same drawing is always derived from an existing frame: ChatGPT redraws every frame from scratch, so the dog would tremble.
- **A raised part of the back looks like a lump** (Vatra, 4.10.2026). The first version of breathing first raised a piece above the loin, then a wider arc, and the right end of the piece dropped by two pixels in the middle of the flat back. To Vatra it looked "like something is growing out of her lower back". Of three variants (whole back at once, whole back in two steps, no breathing) he chose the whole back at once. The rule for moving an outline by one pixel: the end of the raised part goes inside a flat run or next to a column that is already higher, so the outline never jumps by two pixels. Variants are shown on one page, enlarged and at real size, before they go into the mod.
- **Sniffing a spot** (0.8.0, 6.10.2026). `assets/src/sniff.png` (ChatGPT, prompt in `assets/ref/chatgpt-project.md`): slowing down with the head lowering, a 4-frame walk with the nose to the grass, standing and sniffing one spot. Factor 6.0 makes her as long as standing and running. With the head down the top quarter of the figure is the tail and the back, not the ear, so the frames are aligned on the nose (`NOSE_X`, at the x of a running frame's nose). `sniff_bob()` derives `sniff-up` from sniff-5 by raising every column from `SNIFF_HEAD_X` (46) by one pixel: the head and ears, never the front legs. `run_sniff_scene` plays sniff-0, three bobs (`SNIFF_BOBS`), sniff-0 again, about 2.5 s. **The nose-down walk (sniff-1 to 4) is built but not used**: ChatGPT put the same front leg forward in frames 2 and 4, a second ChatGPT sheet looked like she could not move her legs, and swapping the near and far leg colours in the second half of the step made the front leg move too much (all three rejected in motion by Vatra). 1 to 5 spots in a row with a short dash between them were rejected too ("not like Ferro"; she walks between sniffs, she does not run). Vatra: one sniff and that's it.
- **Several stops per turn: programs drawn in Python, not composed in the mod** (6.10.2026). Every order of every kind was ruled out once Vatra said not every kind has to come and more kinds are coming (the orders multiply). Composing at run time in the mod would give a fresh order every turn, but it moves the timing and the ball logic from Python to TS, and the preview would no longer show what the mod plays. With programs, all scene logic stays in `scene.py` and `programs.html` shows exactly what can play. If ten programs per background ever feel repetitive, raise `PROGRAMS` (each adds 36-38k to `scene.ts`, with its ball piece) before moving to run-time composition.
- **The tongue has three shades** (0.9.2, 7.10.2026). Vatra wanted the shaded tongue ChatGPT draws, not one flat pink. The middle shade is the old tongue colour (`#e7766f`), the dark and light ones are 0.78 and 1.2 times it (`TONGUE_SHADES`). `tongue_shades` in `build.py` takes every pink patch of at least 60 source pixels (blue about as strong as green, which leaves out tan fur and orange ears) and gives each pixel the shade nearest to its brightness relative to the patch's average, so a tongue in any pink averages to the middle shade. `downsample` lets the shades vote together, or a tongue split into shades would lose blocks to the fur. With one colour only the brighter half of a tongue passed `tongue_mask` and the darker half went to brown fur: the running tongues had a brown top, now dark pink (6 run frames changed, 8-9 pixels each; no other frame).
- **Drinking from a bowl** (in progress, 7.10.2026). `assets/src/drink.png` (ChatGPT, prompt in `assets/ref/chatgpt-project.md`): slowing down, drinking with the head down, head halfway up, licking the lips, standing. ChatGPT's tongue there is recoloured to the palette hue with its shading kept. Built at factor 6.5 and aligned on the front toes, both not yet checked by eye; not in the mod yet. The bowls and water drops: `assets/src/bowl.png` (ChatGPT, 7.10.2026, message in `assets/ref/chatgpt-project.md`) has three bowls (red, steel, blue) and five drops. With her muzzle under the water she looked like she was drowning (Vatra, 7.10.2026: the tongue is there to lap the top of the water). So in a scene the bowl is split below its water: the rim and the water go behind her, the wall below them in front. - **Measures in a ChatGPT message** (Vatra, 7.10.2026: always write it the measures). Pixel counts alone are not kept: the first prop sheets asked for "about 12 pixels wide and 8 tall" and the like and came out 1.4 to 2.5 times bigger (rock 19x12, sword 15x41 for 9x30, tower 57x67 for 14x30, town 155x55 for 60x22, measured with `props.py`). So every message gives its measures three ways: the whole image as a grid of big pixels ("128 pixels across and 64 down, every pixel one solid square block, 1/128 of the image width"), each object in those pixels, and each object as a share of the image ("less than half the height of the image"). ## Development and install
- Check: `claude plugin validate ./plugin`. Tests: `claude plugin test ./plugin`.
- Installed from this folder: `claude plugin marketplace add`, then `claude plugin install cc-mod-ferro@cc-mod-ferro --scope user`. Installing COPIES the plugin into the cache, so a change in the repo does not apply by itself: raise `version` in `plugin/.claude-plugin/plugin.json`, run `claude plugin update cc-mod-ferro@cc-mod-ferro`, then a new session. **`/reload-plugins` does not pick up the new version** (measured 6.10.2026, 0.7.1 -> 0.7.2, CLI 2.1.286): after the update the reload rewrote the session's marker in `0.7.1/.in_use/` and the session kept running the old code. Sessions that are already open keep the old version until they end. Which version is still in use shows in `~/.claude/plugins/cache/cc-mod-ferro/cc-mod-ferro/<version>/.in_use/` (one file per process).
