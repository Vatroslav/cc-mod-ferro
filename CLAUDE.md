# mod-ferro

A Claude Code mod for fun: Ferro (Vatra's dog, a female Norwich Terrier) runs across a pixel-art meadow in a band above the prompt while Claude works on a long turn. Built 3-4.10.2026. Vatra wants nothing interactive ("so I don't miss anything when I'm not looking"), so the mod only displays. The leverage check from `personal-os/tasks/someday/claude-code-mods.md` was skipped on purpose, because fun is the only goal.

## How it works
- `turn.start` starts two timers: after 20 s the phase is `run`, after 3 min `sleep`. `turn.complete` of the main turn (no `agentId`) cancels them and resets the phase to `null`. The phase lives in `$.state` (`mod-ferro.phase`).
- **The background is random per turn** (Vatra, 4.10.2026: "Random"). `turn.start` draws an index into `SCENES` (`mod-ferro.scene`), so running and sleeping in the same turn share a background. The list of backgrounds is `BACKGROUNDS` in `build.py` and in `scene.py` (there with the place for the alt text, e.g. "the autumn meadow"). Built: `meadow` (summer), `autumn` and `winter`. The mod picks only from `IN_MOD` in `scene.py`: summer and autumn. Winter is switched off for now (Vatra, 4.10.2026); it is still built and previewed, so turning it on is one word in `IN_MOD`.
- `ui.render` on `AbovePrompt` draws an `Svg` only on Desktop, while `isWorking` is true and the phase is not `null`. All animation is SMIL inside the SVG, and the mod draws it once.
- Width: `bodyColumns * 8` CSS px, at most 1280. Without an explicit `width` the frame stays at 300 px. The 8 px per column ratio was measured on 4.10.2026 on the TV (94 columns, ~753 px), not yet on the monitor. The scene has `preserveAspectRatio="xMidYMid slice"`, so a narrower band crops the edges of the scene and the pixels stay 2 CSS px.

## What the Desktop band lets through (test 4.10.2026)
- Allowed: `<path>`, `<rect>`, `<use href>` and `<use xlink:href>`, `<pattern>`, nested `<svg>`, `<text>`, SMIL (`animate`, `animateTransform`, `set`).
- **`<image>` with a PNG data URI does NOT render.** So every drawing is vector strokes: one `<path>` per colour (a stroke of width 1 per horizontal run of pixels) in `<defs>`, and the scene places them with `<use>`.
- The `Svg` element limit is 131,072 characters. Running is ~110k and sleeping ~85k on the summer and autumn meadows, ~117k and ~92k on the more detailed winter one (measured 4.10.2026). Measure every new drawing or scene first: `python tools/scene.py` prints the sizes.

## Drawings and tools
- `assets/src/` holds the original ChatGPT drawings: `run.png`, `poop.png` and `sleep.png` (6 frames each on a magenta background), `meadow.png` (summer meadow, 3:2, nearly seamless) `autumn.png` and `winter.png` (same composition, 4.10.2026). The prompts and the template for a new background are in `assets/ref/chatgpt-project.md`. Key parts: "Norwich Terrier", "side view facing right", "same ground baseline", "flat solid pure magenta (#FF00FF) background", and for backgrounds "edges must match seamlessly".
- `tools/build.py` → `assets/px/`: cuts the frames, removes the magenta, downsamples to a true pixel grid (run factor 6, the rest ~5.5 so the dog is the same size), maps to the shared palette, smooths the edge and aligns the frames on the right ear and the ground. Each background is split into three layers. The split expects the meadow composition: the sky is the most common colour of the third row, the hills start 3 rows above the block of rows that are at least a third not sky and run unbroken to the bottom (white counts as not sky, for snowy hills; the clouds sit above a gap of clear sky), and the grass starts at the first row with 60% light green (yellow-green autumn grass passes too). A ground that is not green (snow) starts on the row after the darkest row under the bushes. Check a new background on the real image before using it: `meadow()` prints where the hills and the grass start, and the summer and autumn layers must stay unchanged (`git status assets/px`).
- **Clouds have their own palette** (4.10.2026): the sky colour plus two cloud colours (white and light-blue shading), computed from the cloud pixels above the hills alone. In the shared 48-colour palette the shading merged into the sky or a grey-green, so the summer clouds were flat white blobs and the autumn ones fell apart into fragments. With it, the summer clouds also got their light-blue underside back, as in the source.
- **The dog palette is frozen** in `assets/palette.json` (4.10.2026): 22 fur and outline colours (`fur`), the tongue and the eye highlight. Median cut + k-means over all images computed it originally; now `build.py` only gives each pixel the nearest colour from the file. Freezing changed no pixel. A new palette from the images is computed only deliberately: `python tools/build.py --new-palette`, which shifts the colours of every animation. A colour added to `fur` does not change existing colours, but it can take over pixels of existing drawings it is closer to, so after a build `git status assets/px` shows which frames changed. Each background has its own palette (48 colours, from its own image only), so a new dog drawing does not touch it.
- **Extra background colours** (`EXTRA_COLORS`, 4.10.2026): median cut gives colours by pixel count, so the brown trunks and twigs of the winter meadow (under 1% of the pixels) turned near black. For a background listed there, pixels the 48 colours miss by more than 60 (sum of channel differences) get 4 colours of their own (median cut + k-means), and every pixel goes to the nearest colour of the larger palette. Only winter uses it, so the approved summer and autumn layers did not change.
- `tools/scene.py` → `plugin/hooks/scene.ts` (generated, do not edit) and `preview/*.svg`: `run.svg` and `sleep.svg` for the summer meadow, `<name>-run.svg` and `<name>-sleep.svg` for the others. `preview/*.svg` is committed (since 4.10.2026), because the README shows them as animation: commit them after every new scene.
- **The repo is public (since 4.10.2026, portfolio).** The README must stay accurate when a drawing, a scene or a number (scene sizes, phases) changes.
- `tools/preview.py` → an enlarged PNG of all frames, for checking by eye.
- `tools/ref_sheet.py` → `assets/ref/ferro-ref.png`, the reference sheet for ChatGPT: two enlarged figures (standing, running with the tongue out), the frozen palette and all frames, on magenta, 1536x1024. It is built from `assets/px`, so regenerate it after reworking a drawing or the palette.
- Preview in a browser: `preview/index.html` shows all scenes of all backgrounds. Vatra watches it in his Chrome (Personal profile), not in the Browser pane. In personal-os `preview_start ferro` serves `preview/` on port 8767 (for screenshots).

## Learned
- **An installed mod does not run in a normal session without a flag** (4.10.2026). Mods of installed plugins sit behind Anthropic's rollout switch, which is off for Vatra's account (`"tengu_plugin_hooks_modules": false` in `~/.claude.json`). Desktop 2.1.286 then does not run the hooks of installed plugins. A mod from `~/.claude/dev-mods` with hot reload on bypasses the switch, so the test in the session worked and the installed version did not. With hot reload on in a session, the installed one works too. The permanent fix is `"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"` in the `env` block of `~/.claude/settings.json`. Check the mod in a normal session only in a new session without hot reload.
- **Gallop order:** ChatGPT laid the run frames out without the order of the phases and Ferro looked like she was running backwards. The real order is `[4, 3, 2, 5, 0]` (`RUN_ORDER`): stretched, landing on the front legs, hind legs forward, gathered, push-off. Frame 1 is left out.
- **Tempo:** 0.13 s per frame, because at 0.085 s the legs looked like they twitched. The grass moves at 80 px/s, although a paw on the ground moves ~42 px/s. Vatra prefers a faster background to a perfect stride, and grass blades over the paws did not help.
- **The tongue, eyes and edge were broken by `build.py`, not by ChatGPT** (4.10.2026). The source has a pink tongue (~170 pixels per dog) and a white eye highlight (2-8 pixels), but downsampling turned the tongue maroon (too few pixels for a colour of its own in median cut) and lost the highlight (never the most common colour in a 6x6 block). About 6,400 pixels of magenta fringe next to the background entered the palette as maroon, hence maroon dots along the outline and maroon ears. The fix: the magenta fringe goes to the background, the tongue and the highlight have reserved colours, each highlight becomes one white pixel on the dark eye, and the edge is cleaned (stray pixels and side bumps removed, fur next to the background becomes outline). Without the k-means refinement median cut lost the neutral dark grey and the saddle got brown blotches. The ear used for alignment is measured before the edge is cleaned, so the frame positions stayed the same. Do not "fix" in ChatGPT what downsampling eats - check the source first. Vatra saw the fix in the installed 0.2.1 (4.10.2026).
- **Expansion plan** (Vatra, 4.10.2026): more animations and backgrounds in a consistent style. The palette was frozen before Ferro's design is final, because reworking a drawing with a frozen palette still works. The reference sheet is ready (`assets/ref/ferro-ref.png`), and the ChatGPT Project instructions and message templates are in `assets/ref/chatgpt-project.md`. The autumn and winter backgrounds are in. An animation with a prop (ball, bone) needs `build.py` reworked: it treats every figure narrower than 20 pixels as the pile from `poop.png`. In the Project, attach the reference sheet to every message - the OpenAI documentation does not say that the image generator sees images from the project files.
- **Breathing in sleep is done in code, not in ChatGPT** (4.10.2026). Breathing used to alternate between two ChatGPT drawings (sleep-4 and sleep-5), which are two different poses, so the picture jumped. Now `build.py` derives `sleep-breath-1` from sleep-5: the whole back from the loin to the neck (columns 17-35) raised by one pixel, with the head, tail and paws in place. `scene.py` loops it by `BREATH` (still 1.8 s, inhale 1.2 s: 3 s per breath), and sleep-4 stays the last step of the intro. A subtle movement on the same drawing is always derived from an existing frame: ChatGPT redraws every frame from scratch, so the dog would tremble.
- **A raised part of the back looks like a lump** (Vatra, 4.10.2026). The first version of breathing first raised a piece above the loin, then a wider arc, and the right end of the piece dropped by two pixels in the middle of the flat back. To Vatra it looked "like something is growing out of her lower back". Of three variants (whole back at once, whole back in two steps, no breathing) he chose the whole back at once. The rule for moving an outline by one pixel: the end of the raised part goes inside a flat run or next to a column that is already higher, so the outline never jumps by two pixels. Variants are shown on one page, enlarged and at real size, before they go into the mod.
- **sleep-4 has one stray pink pixel** on the edge of the right ear (x 54, y 27): `tongue_mask` took the orange ear for the tongue. It shows only for 1 s in the sleep intro.
- **Seamless loop:** the second run lasts so long that the ground travels exactly 20 meadow widths in one loop and the hills (0.35 of the speed) exactly 7. The loop is computed from each background's own width (all three are 154 pixels).

## Development and install
- Check: `claude plugin validate ./plugin`. Tests: `claude plugin test ./plugin`.
- Installed from this folder: `claude plugin marketplace add`, then `claude plugin install mod-ferro@mod-ferro --scope user`. Installing COPIES the plugin into the cache, so a change in the repo does not apply by itself: raise `version` in `plugin/.claude-plugin/plugin.json`, run `claude plugin update mod-ferro@mod-ferro`, then `/reload-plugins` or a new session. Sessions that are already open keep the old version until a reload runs in them. Which version is still in use shows in `~/.claude/plugins/cache/mod-ferro/mod-ferro/<version>/.in_use/` (one file per process).
